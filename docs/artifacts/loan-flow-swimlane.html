DigiLibrary Loan Flow

How a book-loan request travels across four participants — the user’s Lightning component, the Apex service layer, the Open Library API, and the Salesforce data store with its trigger — including the “is the book in the catalogue?” branch and the availability check that gates the loan.

How it runs

  1. The user types a title or author (≥ 2 characters) and presses Search; the LWC calls LibraryService.searchBooks imperatively.
  2. searchBooks runs a SOSL FIND over Library_Book__c, a best-effort callout:Open_Library/search.json, and a SOQL backfill (WHERE Name IN …) for external titles SOSL hasn’t indexed yet.
  3. The merged BookSearchResult list returns; each row is marked LOCAL or EXTERNAL, and the UI renders "Request loan" or "Register / Import" accordingly.
  4. If the book is external only, the user clicks Register / Import; importBook de-dupes by Name and inserts a Library_Book__c with one available copy. The search re-runs and the row is now LOCAL.
  5. The user picks a borrower and clicks Request loan; libraryLoanButton calls requestLoan(bookId, borrowerId).
  6. loanBook selects the book FOR UPDATE and checks Available_Copies__c > 0. If not, it throws NoAvailableCopiesException, which requestLoan re-raises as an AuraHandledException → error toast.
  7. Otherwise it inserts the Library_Book_Loan__c. The after insert trigger re-checks availability (blocking with addError under a race) and decrements Available_Copies__c.
  8. requestLoan returns the new loan Id; the button shows a success toast and fires loancreated, which publishes on LibraryRefresh__c so the book and loan lists reload.
